# 수면 녹음 앱 개발 지침

## 목적

-   사용자는 **수면 질 분석을 위한 음성 기록**이 필요하다.
-   직접 분석하지 않고, **원본 데이터를 충실히 기록하여 전문가에게
    전달**하는 것이 목적이다.

## 기본 원칙

1.  **기록 충실성 최우선**
    -   오디오 이벤트를 놓치지 않도록 안정적인 기록이 핵심.
    -   분석용이므로 손실 압축 대신 **원본 또는 무손실
        형식(PCM/WAV/FLAC)** 유지.
2.  **불필요한 기능 배제**
    -   실시간 분석, 코골이 탐지 등은 필요하지 않음.
    -   앱은 **경비원처럼 기록만 잘 남기는 역할**에 집중.
3.  **안정성 확보**
    -   장시간(8\~10시간) 연속 녹음 가능해야 함.
    -   드롭/중단 없는 연속성 보장.
    -   파일은 30분 단위로 **롤링 저장**하여 손상 위험 최소화.

## 기술 요구사항

### 오디오 캡처

-   **샘플레이트:** 16 kHz
-   **채널:** 모노
-   **비트 깊이:** 16-bit PCM
-   **오디오 소스:** UNPROCESSED 우선, 불가 시 VOICE_RECOGNITION
-   **API:** Android `AudioRecord`

### 버퍼링 & I/O

-   **DirectByteBuffer** 사용, GC 영향 최소화.
-   **SPSC 링버퍼**로 캡처-쓰기 분리, lock-free 구조.
-   **배치쓰기:** 0.25\~0.5초 단위로 파일에 기록.
-   **파일 롤링:** 30분마다 새 파일 생성, WAV 헤더 안전 갱신.

### 파일 포맷

-   **WAV:** 기본 포맷, 헤더 포함 원본 저장.
-   **FLAC:** 선택적 무손실 압축 옵션.
-   **MediaStore** 활용: `IS_PENDING` 플래그로 안전하게 기록.

### 서비스 구조

-   **Foreground Service**로 동작, 지속 알림 표시.
-   **스레드 우선순위:**
    -   캡처 스레드 → `THREAD_PRIORITY_AUDIO`
    -   쓰기 스레드 → `THREAD_PRIORITY_BACKGROUND`

### 안정성 체크

-   **Soak Test:** 8\~10시간 연속 테스트에서 드롭 0건 확인.
-   **로그:** 버퍼 충만율, 파일 쓰기 지연 기록.
-   **충전 상태 사용 권장**, 저장공간 충분히 확보.

## C++ (NDK) 고려 사항

-   Kotlin만으로도 충분히 안정적.
-   단, 아래 상황 발생 시 **NDK 모듈 도입** 검토:
    -   특정 기기에서 AudioRecord 드롭 발생.
    -   GC로 인한 드문 지연 발생.
    -   저지연/성능 모니터링 필요(Oboe/AAudio).

## 사용자 인터페이스

-   **단순 제어 UI**
    -   \[녹음 시작\] 버튼
    -   \[녹음 중지\] 버튼
    -   상태 표시 (예: "녹음 중", "파일 저장 완료")

## 최종 개념

-   앱은 **유능한 경비원**이다.
    -   밤새 **충실히 일기를 기록**.
    -   기록은 **WAV/FLAC 파일**로 안전하게 보관.
    -   아침에 사용자는 그대로 전문가에게 전달.
